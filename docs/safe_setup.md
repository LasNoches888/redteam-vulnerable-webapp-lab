# Безопасный запуск намеренно уязвимого стенда

Стенд содержит реальные уязвимости. Любой, кто сможет подключиться к порту, получит те же возможности, что и вы.

## Правила
1. Запускайте только на своей машине или в изолированной виртуальной сети.
2. **Не публикуйте порт 5000 в интернет** и не запускайте стенд на сервере с публичным адресом.
3. Не размещайте на стенде реальные данные и пароли — в нём только вымышленные учётные записи.
4. После занятия останавливайте контейнер: `docker compose down`.

## Привязка порта к localhost
В `docker-compose.yml` запись `"5000:5000"` публикует порт на **всех** сетевых интерфейсах хоста — стенд станет
доступен из локальной сети. Ограничьте публикацию адресом loopback:

```yaml
services:
  web:
    build: ./app
    ports:
      - "127.0.0.1:5000:5000"
```
После этого приложение доступно только с вашей машины.

## Изолированная сеть без выхода наружу
Если хотите запретить стенду исходящие соединения:
```yaml
services:
  web:
    build: ./app
    ports:
      - "127.0.0.1:5000:5000"
    networks: [lab]

networks:
  lab:
    internal: true
```
Внимание: при `internal: true` Docker не публикует порты на хост; для доступа из браузера используйте
сеть без `internal` или проброс через отдельный прокси-контейнер.

## Проверка, что порт не торчит наружу
```bash
docker compose up -d
ss -ltn | grep 5000          # ожидается 127.0.0.1:5000, а не 0.0.0.0:5000
```
