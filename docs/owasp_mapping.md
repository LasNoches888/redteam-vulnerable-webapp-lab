|-------------------|---------------------|-----|------------|-------------|
| SQL-инъекция в `/login` | A03: Injection | CWE-89 | `app/app.py`, функция `login` | параметризованные запросы (`?`) |

## Как думать о защите

1. **Не доверяйте вводу.** Любые данные от клиента — параметры, заголовки, cookie — считаются недоверенными.
2. **Разделяйте код и данные.** Параметризованные запросы и экранирование по контексту убирают целый класс уязвимостей.
3. **Минимум привилегий и минимум данных.** Возвращайте только нужные поля, БД-пользователь приложения не должен быть администратором.
4. **Эшелонированная защита.** Заголовки безопасности (CSP, `X-Content-Type-Options`), `HttpOnly`-cookie, WAF — дополняют, а не заменяют исправление кода.
5. **Автоматическая проверка.** Статический анализ (например, `bandit` для Python) находит конкатенацию SQL на этапе review.
